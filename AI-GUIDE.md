# AI-GUIDE — how to change this laboratory

The orientation document. `MAP.md` (generated by `./map.ps1`) says *where*
everything is; this says *how* to change it and what will bite you.
**`MASTER-PLAN.md` says what is built, what is left, and the rules anything new
must be written to** — read it first if you are choosing work rather than
editing something already chosen.
**`SITE-RULES.md` outranks both** — the laws the site obeys, and the rule that a
defect found in one wing is fixed in every wing it exists in. Read it before
settling any question of what is allowed; read this before typing.

---

## 1. What this is

A single self-contained page — no build step beyond concatenation, no
dependencies, no network. 40 wings, 604 guided experiments, 182 canvas stages,
4249 unit tests (measured 2026-08-14 — **re-measure rather than quote**;
`./auditdocs.ps1` fails the build when a figure here drifts from the site).
Everything on screen is computed live from the actual mathematics: symbolic
differentiation, adaptive quadrature, a nodal circuit solver, Lorentz boosts,
Schwarzschild geodesics, exact wavefunctions.

```
src/head.html      <- <meta>, title
src/styles.css     <- the whole design system
src/shell.html     <- the DOM skeleton (header, canvas, dock, rail, palette)
src/js/*.js        <- 235 modules, concatenated in filename order
        |
        v  ./build.ps1
vector-calculus.html   (5 409 933 bytes on 2026-08-14, the deployable artifact)
```

**Never edit `vector-calculus.html`.** It is overwritten on every build.
**Nor any generated document** — `MAP.md` comes from `./map.ps1`.

## 2. The loop you will actually run

```powershell
./build.ps1        # src/ -> vector-calculus.html          (~1 s)
./smoke.ps1        # does the bundle parse and boot at all?              (~10 s)
./runtests.ps1     # 4375 engine unit tests, must say "0 failed"   (~30 s)
./runstagetests.ps1 # stage helpers called directly, two routes each (~30 s)
./measure.ps1      # the headline counts, from the booted app         (~15 s)
./auditdocs.ps1    # do these documents still describe the site?     (~1 min)
./auditdocs.ps1 -Fix   #   ... and rewrite the stale counts, then read the diff
./auditcontrast.ps1 # WCAG contrast + the 12px type floor              (~1 s)
./map.ps1          # regenerate MAP.md after adding/renaming files
./runapp.ps1 -Wing integral -Demo '1.0' -Tag x    # screenshot one demo
./runall.ps1       # full audit: every demo, every control  (~18 min)
./auditcustom.ps1  # drive the "type your own" path on every stage    (~1 min)
./auditclaims.ps1  # recompute what the preset tables assert          (~30 s)
./auditlink.ps1    # does a permalink reproduce the view it was copied from? (~2 min)
./auditpanel.ps1   # leave every stage and come back — do the panels survive? (~20 s)
./auditperf.ps1    # what a frame costs        (~40 s; -Where attributes it)
./auditzoom.ps1    # pan/zoom every plot, and prove mkPlot's identity (~1 min)
./auditframe.ps1   # does any curve leave the window it was framed in? (~1 min)
./auditmarks.ps1   # are the key points drawn on a plot real?         (~1 min)
./auditticks.ps1   # duplicate tick labels + headings under the chip  (~1 min)
./auditresid.ps1   # is any residual printed as though it were a measurement? (~1 min)
./auditsides.ps1   # do a stage's two routes AGREE, on every preset?    (~2 min)
./auditsize.ps1    # eight canvas shapes — layouts that break at another ratio (~2 min)
./auditviewport.ps1 # sixteen real window sizes, and the page around the canvas (~3 min)
./auditartifact.ps1 # does it survive publication as a Claude artifact? (~1 min)
./audittext.ps1    # harvest what every panel SAYS         (~4 min)
./auditscan.ps1    # scan that harvest for notation defects (~20 s)
./auditderive.ps1  # measure every derivation ladder       (~40 s)
./auditprose.ps1   # inventory what the essays assert       (~1 s, reads the harvest)
./clean.ps1        # delete everything the above regenerate (~2 s, -WhatIf to list)
```

That is the whole harness — `Get-ChildItem *.ps1` is the authority on how many
there are, and `./auditdocs.ps1` fails if a script exists that this list, or
`MASTER-PLAN.md` §1.6 and §4.2, does not mention.

`runall.ps1` proves every demo *runs*. `audittext.ps1` + `auditscan.ps1` prove
every demo is *readable* — they drive all 604 experiments, harvest the
`textContent` of every panel a student reads, and scan for ASCII stand-ins,
leaked markup, empty panels and `NaN`. Run them on **rendered output**, never on
source: grepping `src/` for `sqrt` drowns in `Math.sqrt(` and `theta` drowns in
variable names.

**Both audit scripts must be saved with a UTF-8 BOM.** PowerShell 5.1 reads a
BOM-less `.ps1` as ANSI, and the Unicode in their patterns becomes mojibake that
fails to parse. This has already bitten twice.

`runall.ps1` must end `caught=0 OK`. It takes ~18 minutes — **run it in the
background**, a foreground call hits the 10-minute shell limit.

`auditpanel.ps1` must end `bad=0`. **The three panels are stateful.**
`refreshStageReadout`, `refreshDerive` and `updateStageChip` all write through
`uiSetHtml` (`80a-ui-core.js`), which **skips a write whose HTML matches what it
last wrote** — that is worth ~2.8 MB/s of DOM churn, and it means the cache
marker must always describe what is really in the element. **Every write to
`#stageReadout`, `#deriveBody` and `#chip` must go through `uiSetHtml`.** A
direct `el.innerHTML = …` leaves the marker describing a DOM that is gone, so
the next identical refresh is skipped and the panel silently keeps stale content
or none. On 2026-08-13 `stageExit` doing exactly that blanked **145 of 178 stages**
on re-entry while `runall` still reported `caught=0` — it visits each demo once and
never returns to one. `smoke.ps1` greps for the cause; this measures the effect.

`auditcustom.ps1` must end `bad=0 OK`. It covers the one thing `runall` cannot:
runall drives every control a stage already shows, but it never *chooses* the
`custom` option, so the whole reader-supplied-function path is invisible to it.
Two bugs shipped through that blind spot in a single afternoon. Run it after any
change to a picker, an accessor or the `pk*` helpers. It drives `<textarea>`
inputs too — the netlist and the lens prescription are not one-line formulas —
and a textarea must carry a `data-audit` attribute holding something valid for
its own format, because no generic expression could be.

`auditlink.ps1` must end `findings=0`. A permalink puts the reader's whole view
in the URL (`#w=<wing>&d=<group.item>&c.<id>=<value>`) and restores it by driving
the real controls, so it is the one gate that asks whether every control's value
can be written **back**. Three things follow for anything you add:

- **An element id is a key.** Two panels both using `ciR` meant `getElementById`
  returned whichever came first, and a `wireSlider` call could attach to the
  wrong element entirely. The gate fails on any duplicate id under `#dock`.
- **Never fill a box the reader types into with `fmtNum`.** It emits U+2212 and
  real superscripts, and `parseFloat('−0.7')` is `NaN`. Three panels did, and
  every negative component of û and n̂ silently became `0` through a `|| 0`.
  Use **`fmtEdit(v, sig)`** for anything typed into, `fmtNum` for what is read.
- **A control read as part of a group** — û is `du`/`dv`/`dw`, one handler, one
  re-normalisation — must tolerate all of it being assigned before any of it is
  notified, which is how `plApply` restores.

It runs two routes, because the obvious one is worthless alone: comparing the
**controls** still passed on a build where the restore filled every box and told
no stage anything, so it also compares the text the visible panels **print from**
those controls.

## Printing a difference — pick the helper, never the raw number

Four formatters, and the choice is mechanical (`10-math.js`). A residual is
meaningless without the scale it is read against, so **none of these is
`fmtNum`**, whose `sig` counts *decimals* below 1 and renders a real gap in
[1e-4, 5×10⁻ˢⁱᵍ) as the string `0`:

| you have | use |
|---|---|
| **both routes** in scope | **`fmtAgree(a, b, unit)`** — derives the scale from the two numbers, so it cannot be handed the wrong one. Reach for this first |
| only the gap | `fmtGap(gap, scale, unit)` — an accumulated drift, a worst case over a sweep |
| either, on a **canvas** | `fmtAgreeTight` / `fmtGapTight` — same verdict and floor, no prose, Unicode only, fits a fixed column |
| a magnitude whose whole meaning is its size | `fmtSig(v, sig)` — never `toFixed`, which printed a perfect fit as `0.00000` |
| inside a circuit | `ckGap` / `ckEngF` (`48a`) |

**`toExponential` is not one of them.** It emits ASCII `8.10e-11` where the site
requires `8.10×10⁻¹¹` (§1.7), and it carries no scale at all.

The gate is `./auditresid.ps1`, and it reads **five rendered surfaces** —
readout, chip, derive ladder, legend, and the `*Own` reader-supplied panels.
It cannot read a **canvas**, so a `ctText`/`wsNum`/`rlText` that prints a
difference is on you.

`auditderive.ps1` must end `flagged=0 OK`. It calls every stage's `derive(st)`,
which **nothing else does** — not `runtests`, which only sees engines, and not
`runall`, which never opens the ladder. A template hole that throws there is
invisible to both, and one was: `ckLab` referenced a bare `Δ`. It also measures
whether the `drvSay` rungs carry reasoning or merely restate the algebra, which
is the rule §3b states and nothing used to check. Its one blind spot is recorded
in the script: it sees only the ladder a stage builds in its **default** state,
so a `derive()` with more than one return needs reading by hand.

`auditprose.ps1` costs a second and reads `audittext-dump.json` rather than
driving a browser, so run `audittext.ps1` first. It inventories the essays for
phrases that decline to justify a result, and for named theorems the prose leans
on with no statement card behind them. It is an inventory, not a pass/fail —
some entries are legitimate cross-references and it labels them as such.

Two things that will waste your time if you do not know them:

- **Concurrent Chrome runs need separate `--user-data-dir`.** Two harnesses
  sharing `./cprof` silently corrupt each other's output.
- **Do not pipe native executables through `2>&1` in PowerShell 5.1.** It wraps
  stderr in ErrorRecords and reports failure on a successful run. Chrome writes
  harmless noise to stderr on every launch.

## 3. Recipes

### Change what a demo says or does
Find it in `MAP.md` → the wing's `72*-demos-*.js`. Each entry is:

```js
{ n:'Display name', ex:'display formula', stage:'stageId', opts:{…},
  out:'The outcome the reader should see.',
  note:'Why the mathematics produces it.' }
```

`out` and `note` are HTML and are passed through `supify()`, so `e^(-x^2)` in the
source typesets as a real superscript.

### Change what a demo *computes*
That is the stage, not the demo. `MAP.md` → stage id → file. Stages are
`STAGES.<id> = { title, enter, controls, wire, frame, readout, chip, legend }`.

### Change the prose essay behind "The mathematics"
`MAP.md` → the wing's row → prose column. One wing per file in `85*`/`86*`/`87*`.
Routed by `THEORY_BY_WING` in `82-ui-wings.js`; a wing missing from that table
falls back to the bare `THEORY` constant.

### Change a physical constant
Engines only, `21`–`49`. Constants are pinned by `tests.js`, so update both, and
record it in `AUDIT.md` with the source (CODATA 2022 / PDG 2024). If the value
appears anywhere else as a literal, replace that literal with the constant —
duplicated constants drift.

### Add a wing
Seven places:
1. `src/js/72*-demos-<wing>.js` — a new `*_GROUPS` array
2. `src/js/72zz-wings-registry.js` — the `WINGS` entry (it must sort last of the 72s)
3. `src/shell.html` — a menu item in the right `.navgroup`, and a home card
4. `src/js/81-ui-nav.js` — `NAV_GROUP_OF`
5. `src/js/82-ui-wings.js` — `WING_SECTIONS` and `THEORY_BY_WING`
6. the theory file
7. `runall.ps1` (both wing lists) and `README.md`

Then `./map.ps1`.

## 3b. Letting the reader supply the conditions

Every experiment should be answerable with the reader's data, not only the
author's preset. `src/js/59-interact.js` provides four mechanisms; a stage gets
any of them in a couple of lines.

| prefix | what it gives you | key calls |
|---|---|---|
| `sk` | **sketch pad** — drag a curve, get an interpolated `f(x)` | `skNew(x0,x1,n,f)`, `skPick(sk,P,sx,sy,phase)`, `skAt`, `skFn`, `skPaint`, `skDeriv`, `skIntegral` |
| `lp` | **region tool** — drag a closed loop, get a contour and its interior | `lpNew()`, `lpPick`, `lpArea` (shoelace), `lpPerim`, `lpInside`, `lpParam` (arc-length parametrisation), `lpPaint` |
| `mx` | **matrix editor** — typed entries, live | `mxHtml(id,M,rowLbl,colLbl)`, `mxWire(id,set)`, `mxClone` |
| `fn` | **expression box** — typed formula, compiled | `fnHtml(id,label,src,vars)`, `fnWire(id,set,build)` |
| `pk` | **"or type your own"** on any preset picker | `pkSeg`, `pkBoxes`, `pkWire`/`pkWireBoxes`, `pkOwn`, `pkFn` |

### Typed values everywhere — `ctlSlider` and `wireSlider`

**Every numeric control is already typeable; you get this for free.** `ctlSlider`
emits a `.sldnum` box beside the track, and a typed value is *not* bounded by the
slider's min/max — the thumb pins at the end and the stage uses what was asked
for. `ctlParse` accepts anything the expression engine does, so `pi/4` and
`sqrt(2)` are valid entries.

Pass a fifth argument to `wireSlider` only for a limit that is **physics, not
widget**: `{lo, hi, why}`, or a function returning that when two controls
constrain each other (`RL_BETA_LIM`, and the rotating disk, are the examples).
The `why` is shown in the panel's status line — a clamp that moves a number
silently teaches nothing. Counts (step 1 from a positive start) are handled
centrally: rounded, floored at the slider's minimum, capped at ten times its top.

### The `pk*` picker retrofit

The generalisation of `mvPick`. A wing keeps its preset table; these add the
extra option, the boxes it reveals, and storage for what was typed:

```js
const IG_1D_SLOTS  = [{ k:'f', label:'f(x) =', vars:'x', def:'x^2*sin(x)' }];
const IG_1D_BOUNDS = [{ k:'a', label:'from a =', def:0 }, { k:'b', label:'to b =', def:Math.PI }];
function igCur(st){                       // shaped exactly like a table entry
  if(st.key !== 'custom') return IG_1D[st.key];
  const own = pkOwn(st, 'ig1', IG_1D_SLOTS, IG_1D_BOUNDS);
  return { name:…, f:pkFn(st, 'ig1', 'f'), Fi:null, a:+own.a, b:+own.b, … };
}
```

`pkCur`-style accessors are the whole trick: return an object shaped like one of
the wing's own table entries and **every** `TABLE[st.key]` becomes `cur(st)` with
no other change. Storage hangs off the picker id, so two pickers on one stage
keep separate answers.

### Two more picker shapes

Not every wing keeps a table. Where the segmented control's value **is** the
expression, the retrofit is three lines and needs no accessor at all:

```js
pkSrcSeg('clDF', st.src, [['x^2','x²'], …], 'x*sin(x)')   // in controls()
pkSrcBox('clDF', st.src, 'f(x) =', 'x')                   //  "
pkSrcWire('clDF', ST.src, v => { ST.src = v; ST.F = clBundle(v); });  // in wire()
```

The option list is remembered against the picker id, so the box and the wiring
need not repeat a list that is mostly typeset Unicode. The chip's own value must
not be one of the presets or choosing it would just re-select that preset —
`pkSrcSeg` guarantees this, but pass a `def` of your own anyway.

Where the expression is written in a **parameter** rather than in x — a curve in
t, a signal, a forcing term — use `pkParamAst`/`pkParamFn`/`pkParamD`, or
`pkCurve2(xsrc, ysrc)` for a plane curve with its first two derivatives. They
rewrite `t` to x and `a` to y before parsing, because the engine binds `t` to the
animation clock and knows nothing called `a`. **A slot using them must carry
`build: pkParamBuild`**, or `fnWire` will validate the raw text, reject
`a*cos(t)` as an unknown identifier, and silently keep the previous formula.

Three traps, all of which have bitten:
- **Do not `replace_all` `TABLE[st.key]` after writing the accessor** — it
  rewrites the lookup *inside* the accessor and you get infinite recursion.
  Replace first, then add the accessor.
- **Grep for `st.key ===` before adding a synthetic key.** Branches that ask
  which preset is loaded must be told what a custom one counts as
  (`igApplyKind`), or they silently fall through to the wrong arm.
- A property a preset *declares* (`conservative`) must be **measured** for a
  typed one — see `vcScan`, which reports the largest Q<sub>x</sub> − P<sub>y</sub>
  it found rather than asserting anything.
- **Wiring the boxes is a separate step from rendering them**, and forgetting it
  produces no error at all: the field accepts the keystrokes and the picture
  keeps the default. `auditcustom.ps1` compares the readout before and after
  typing precisely to catch that.

Notes that matter:

- A sketch stores **uniform samples**, not a path, so it can be evaluated,
  differentiated and integrated — it is interchangeable with an expression
  anywhere a stage takes an initial condition. That interchangeability is the
  point: "draw the starting temperature" and "type `sin(3x)·e^(−x²)`" should be
  the same feature.
- `lpArea` is the **signed** shoelace area, so its sign is the orientation —
  which is exactly what Green's theorem needs.
- `fnWire` only calls `set` when the expression parses. A half-typed formula
  leaves the previous function in place and shows the error inline, so the
  picture never blanks mid-keystroke.
- A stage that wants pointer drawing must set `drag:true` so it receives
  down/move/up in `pick(st, sx, sy, phase)`.
- Plots expose `invX` **and** `invY`, so a pointer can be read back as data.

### The plot viewport — pan, zoom, clip, overlay

`59c-plot-view.js`. Every flat picture is laid out by `mkPlot`, and there are
259 calls to it, so the viewport lives there and all of them get it at once.

**The identity property is the whole design.** With no reader interaction,
`mkPlot` returns *exactly* the four numbers it was handed. That is what makes
this safe to add under 178 stages that know nothing about it, and
`auditzoom.ps1` asserts it on every one of them. Do not add anything to `mkPlot`
that perturbs the window at rest.

- The view is stored **relative** to the window the stage asked for
  (`{ox, oy, kx, ky}`, identity at `{0,0,1,1}`), so a slider that changes the
  natural window carries the reader's framing with it. Two stages animate their
  own window — `emFaraday` scrolls its time axis, `clLimit` marches in — and the
  relative form is why a zoom survives that instead of being torn off it.
- Views hang off `ST`, so changing demo or stage drops them.
- The key is the plot box **as a fraction of the canvas**, so a view survives a
  resize. Pixels would lose it on every resize; the data window would lose it on
  every slider move.
- `pvClip` confines drawing to the box, and `plotCurve` uses it. It applies to
  `mkPlot` boxes only — a `ctBox` is an aspect-true diagram whose arrows are
  *meant* to reach past the frame, and clipping those deletes information.
- **Zooming out multiplies the data span.** Anything that derives a loop count
  from the span must cap it; `ctGrid` now doubles an explicit step until it
  fits. This is the hang recorded in §7, one zoom gesture away.

Two helpers worth knowing:

- **`mkPlotFit(px,py,pw,ph,x0,x1,fns,opts)`** — the y-window derived from the
  functions rather than guessed. It quantises to a round step, because an exact
  fit recomputed every frame twitches; and it frames the *body* of the function
  rather than its extremes, so a pole does not flatten everything else onto the
  axis. `opts:{ include:[…], symmetric, minSpan, n }`.
- **`pvName(P, label)`** — what the plot is drawing, typeset into its top-right
  corner. Top *right* deliberately: the readout chip floats over the canvas's
  top-left ~180×90 px and a label there is simply behind it. Feed it
  `pkPretty(src)`, never raw `f:`/`src:` ASCII.

`auditframe.ps1` reports curves running outside their window, and classifies
rather than accuses: `LINE` (a tangent or asymptote — clipping is correct),
`POLE` (no window contains it), `MINOR` (<5%), `CUT` (the window is too small).
Only `CUT` is worth acting on, and even then not always — `srTaylor`'s
polynomials diverging outside the radius of convergence *is* the experiment.

### The derivation ladder

**Every one of the 182 stages defines `derive(st)`**, returning
`{title, steps, note}`. It renders into the "Where this comes from" dock
section. Two rung types:

- `drvStep(label, eq, sub)` — a numbered rung. The `eq` stays in **letters**;
  live numbers go only in `sub`. Build the equation with `dv`/`dop`/`dfrac`
  (see `58-derive.js`), never with raw ASCII.
- `drvSay(label, prose)` — an unnumbered rung carrying the reasoning: why the
  step is legal, where the idea comes from, what the usual misreading is.

A ladder that only restates the algebra is not worth adding. The `drvSay` rungs
are the point — they carry what a textbook leaves to a lecturer.

**Two traps, both of which have bitten:**
- A template hole inside a template hole is a parse error the unit suite cannot
  see. `${dfrac('ħ', dv('m')_W dv('c'))}` killed the whole app and
  `runtests.ps1` still reported 2257 passing. **Run `./smoke.ps1` after every
  build.**
- Check the fields you read off `st` and off engine returns actually exist.
  `laRREF` has no `inconsistent`; reading it gave `undefined`, which is falsy,
  which silently reported inconsistent systems as solvable.

### The formal layer — definitions, theorems, proofs

`83-statements.js` gives the essays a citable layer. The essays explain; a
statement card states the thing exactly and proves it.

```js
${stDefn('Continuity at a point', `<p>…</p>`, { see:'limits:0.6' })}

${stThm('Mean Value Theorem', {
  hyp:'…continuous on [a,b], differentiable on (a,b)',
  then:'there is c ∈ (a,b) with',
  eq:'…',                       // stEq() for a display line inside a card
  proof:`<p>…</p>`,             // omit only with `because:` saying why
  note:'the hypothesis people drop',
  see:'limits:0.7' })}          // "wing:group.item" — the demo that shows it
```

`stLemma` and `stCor` are the same call with a different kind. Numbering is
applied **at render time** by `stNumber()` in `openTheory()`, never written into
the source — several essays are assembled from more than one constant, so a
hand-written number restarts the count halfway through. This is the same reason
demo groups are numbered in `80a-ui-core.js` rather than in the tables.

Two things to know:

- **A card is written inside the essay's template literal**, so it is a template
  hole containing a function call containing more template literals. That nests
  three deep and is legal, but it is exactly the shape that has taken the whole
  app down before. **Run `./smoke.ps1` after every card you add.**
- `see:` is resolved at *click* time, not build time, so a renumbered demo
  reports "that experiment has moved" instead of silently doing nothing.

`./auditscan.ps1` prints coverage per wing — how many statements, how many carry
a proof, how many link to an experiment — counted from the rendered essay, so it
measures what a reader can actually reach.

### Retrofitting an existing wing

Prefer patching the **shared picker** over editing stages one at a time. The
partial-derivatives wing gained custom functions across all nine of its stages by
changing `mvPick` alone: it now appends a `custom` option and emits the
expression box, with `mvSetKey`/`mvWirePick` handling the wiring.

The trap that follows is worth knowing before you repeat the pattern: every
caption that did `MV_FUNCS[st.key].name` broke, because there is no `custom`
entry in the table. Anything that indexes the option table by the current key
needs a guard — hence `mvName(st)` / `mvShort(st)`. Grep for
`TABLE[st.key]` before adding a synthetic key to any picker.

## 4. Displaying mathematics

The house rule: **what is shown must be typeset, not spelled out in ASCII.**

| write | not |
|---|---|
| `x²`, `10⁻⁶` | `x^2`, `10^-6` |
| `√`, `∫`, `Σ`, `∂`, `∇` | `sqrt`, `int`, `sum`, `d`, `del` |
| `θ φ ω ψ Ψ α β γ ħ` | `theta phi omega psi Psi alpha beta gamma hbar` |
| `±`, `≤`, `≥`, `≠`, `→`, `×`, `·` | `+/-`, `<=`, `>=`, `!=`, `->`, `x`, `*` |
| `−` (U+2212) | `-` (hyphen) in front of a number |
| `\|↑⟩`, `⟨S⟩` | `\|up>`, `<S>` — angle brackets are eaten as HTML tags |

Three contexts, three rules:

1. **HTML** — `kv()` labels, `<p class="help">`, readouts, theory prose, legends,
   `ctSeg`/`rlSeg` labels. `<sub>`/`<sup>` are fine. Caret exponents are
   converted automatically: `supify()` runs over stage controls, readouts,
   chips, legends, demo commentary and theory prose at render time.
2. **Canvas** — `stageNote`, `ctText`, `R.label`, `ctx.fillText`. **No markup**;
   it is drawn literally. Use Unicode. Unicode has no subscript `y`, `b` or `c`,
   so reword (`∂f/∂y`, "heat in = work out + heat dumped").
3. **Parsed expressions** — `f:`, `P:`, `Q:`, `R:`, `src:` go to the expression
   parser and **must stay ASCII**. The neighbouring `ex:` is the display copy.

`fmtNum()` emits real superscripts (`2.5×10⁻⁶`) and U+2212 minus signs, in both
HTML and canvas. Do not wrap its output in markup.

**`supify()` must never touch text inside a tag.** It converts only the text
between tags, and that is load-bearing rather than tidiness: a segmented control
carries its expression in the attribute itself —
`ctSeg('mvCI', src, [['x^2+y^2-4', 'circle x²+y²=4'], …])` — so rewriting
attributes turned `data-v="x^2+y^2-4"` into `data-v="x<sup>2</sup>+…"` and fed
that to the expression parser. If you extend it, keep the tag-skipping split.

To check your work, render and scan the *output* rather than the source —
grepping source drowns in `Math.sqrt(` and variables named `theta`. Drive every
demo headlessly and scan `textContent` of `#chip`, `#stageReadout`, `#stageBody`,
`#demoNote` and `#theoryProse` for ASCII stand-ins.

## 5. Layout and navigation

```
┌─────────────────────────────────────────────┐
│ topbar: brand · 4 wing menus · ⌕ search · … │
├──────────────────────────────┬──────────────┤
│                              │              │
│           canvas             │  rail:       │
│                              │  guided      │
├──── split ───────────────────┤  experiments │
│  dock: every control panel   │              │
└──────────────────────────────┴──────────────┘
```

- Every control panel lives in `#dock`, a wide multi-column strip **below** the
  canvas. The right rail holds only the guided-experiment list. Anything that
  audits controls must query `#dock`, not `.rail`.
- Both are resized by `.split` bars driving `--rail` and `--dockh`
  (`wireSplitters()`). **Every resize must call `R.resize()`** — the renderer
  keeps its own pixel buffer and CSS alone will not tell it.
- The 40 wings sit in seven dropdown menus. `#wingNav` contains every
  `button[data-w]`, so `markWingNav()` and the boot wiring work regardless of
  nesting; the four menu triggers carry no `data-w` and are skipped.
- **Ctrl/⌘K** opens the command palette, which searches all 40 wings and all 593
  experiments, including their outcome prose.

### Responsive
Three rungs: desktop (three panes), tablet ≤1179 px (rail becomes a slide-over
drawer, one floating "Experiments" button), phone ≤899 px (one pane at a time
from a bottom bar, controls as a bottom sheet, wing menus replaced by search).

**The responsive block must stay last in `styles.css`.** Media queries add no
specificity, so a rule written later in the file beats one inside an earlier
`@media` block. This has already caused one bug where every mobile nav override
was silently ignored.

## 6. Accuracy standards

These are the house style and they are not negotiable:

- A claim that two things are equal is made only after computing **both**
  independently and printing the difference. The difference is the evidence.
- "Exact" means a closed form or adaptive quadrature at 1e-13.
- Convergence rates are **measured** by halving h, never quoted.
- Physics is current: CODATA 2022, PDG 2024, no Bohr orbits, decoherence framing.
- Never let `undefined`, `NaN` or `Infinity` reach a readout string — `runall`
  greps for them, prose included. Write "not defined there" instead.

`AUDIT.md` records what has been verified, what was wrong, and how it was
checked. Add to it rather than starting a new file.

## 7. Where the bodies are buried

- **Silent name collisions.** One script scope. Prefix and grep first.
- **`ctGrid` on an `mkPlot` whose axes carry different units.** It derives a step
  per axis now, but it used to derive one from the *x* span and apply it to both.
  On an aspect-true `ctBox` the spans are equal and that was harmless; on a plot
  with kPa up one side and litres along the other it asked for four hundred
  thousand lines **per animation frame**. The stage does not error — it simply
  stops returning, and headless Chrome never exits because virtual time cannot
  advance while the renderer is busy. If a page hangs with no error, look for a
  loop whose step came from somewhere else.
- **Echoing a typed expression back to the reader.** `f:`/`src:` strings are
  ASCII for the parser, so printing one raw puts `sqrt(z - z^2)` in a readout and
  `auditscan` flags it HIGH. Use **`pkPretty(src)`** (`59-interact.js`), which
  escapes it and converts `sqrt`→`√`, `pi`→`π`, `*`→`·`, `-`→`−`, leaving carets
  for `supify()`. Never feed its output back to `parse()`, and never put it in a
  `<textarea>` — that has to stay editable ASCII.
- **`nqAdaptive`'s 16-panel pre-subdivision** exists because adaptive Simpson
  returns 0 on periodic integrands whose zeros hit its sample points. Leave it.
- **Relativity catastrophic cancellations** must be computed in closed form; the
  tests assert the naive route is wrong.
- **Circuit sign conventions**: the solver uses one convention (`p = v·i` is
  power *absorbed*, which makes Tellegen's sum close). The display layer flips
  voltage sources only. Do not "fix" a source showing negative power in
  `ckMeasure`. A capacitor's current must be read from `e.h.i`.
- **Headless Chrome fires `requestAnimationFrame` only ~3 times.** Animated
  stages look blank in screenshots unless the harness pumps `stageFrame(dt)` by
  hand. Before hunting a logic bug, measure: read canvas pixels via
  `getImageData` and count non-background samples.
- **PowerShell variable names are greedy and case-insensitive.** `"$pm1"` is a
  variable named `pm1`, not `$pm` + `1`; `$T` and `$t` are the same variable.
  Both have already silently eaten text in this repo. Use `$([char]0x00B1)` or
  `${pm}1`.
